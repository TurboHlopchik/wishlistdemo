# Соне — 1 год · список желанных подарков

Статичная страница со списком подарков и общими бронями: если гость нажал
«Подарить», подарок сразу становится занятым для всех остальных.

```
index.html              главная
admin.html              управление списком (пароль)
assets/                 стили, скрипты, картинки
  js/sprite.js          общий SVG-спрайт: иконки + иллюстрации подарков
api/                    серверные функции Vercel
  state.js              GET  — каталог и занятые подарки (без личных данных)
  reserve.js            POST — забронировать / снять свою бронь
  admin.js              POST — вход и всё управление
  _lib/                 хранилище, авторизация, валидация
  _lib/seed.js          стартовые 20 подарков (заполняют базу при первом запуске)
server/dev.js           локальный сервер для разработки
```

---

## Локально

```bash
npm run dev
```

Откроется на `http://localhost:4173`, админка — `/admin`, пароль по умолчанию `alisa`
(меняется переменной `ADMIN_PASSWORD`). Данные лежат в `.data/db.json` — удалите файл,
чтобы начать со стартового списка заново. Ни одной npm-зависимости, только Node 20+.

## Деплой на Vercel

### 1. Хранилище

Брони должны переживать перезапуск функции, поэтому нужен Redis.

В проекте на Vercel: **Storage → Marketplace → Upstash for Redis → Create**.
Vercel сам добавит в проект переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN` —
код подхватит их без настройки. Бесплатного тарифа хватает с большим запасом:
на весь праздник уйдёт несколько сотен запросов.

Если подключаете Upstash напрямую, а не через Vercel, переменные называются
`UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` — они тоже поддерживаются.

### 2. Пароль админки

**Settings → Environment Variables:**

| Переменная | Значение | Зачем |
|---|---|---|
| `ADMIN_PASSWORD` | ваш пароль | вход в `/admin` |
| `ADMIN_SECRET` | длинная случайная строка | подпись куки сессии |

`ADMIN_SECRET` необязателен — без него подпись выводится из пароля, но тогда смена
пароля разлогинит вас. Сгенерировать: `openssl rand -base64 32`.

Без `ADMIN_PASSWORD` админка отвечает «пароль не задан» и не пускает никого.

### 3. Публикация

Проект связан с репозиторием, поэтому выкат автоматический:

```bash
git push
```

Пуш в `main` уезжает в прод, пуши в другие ветки — в отдельные preview-ссылки.
Разово можно выкатить и из терминала:

```bash
npx vercel --prod
```

Первый запрос заполнит базу подарками из `api/_lib/seed.js`. Дальше список
живёт в Redis и правится только через админку — файл сида больше не читается.

## Как всё устроено

**Бронь без гонок.** Занятие подарка — атомарная операция `HSETNX`. Если двое
нажали «Подарить» одновременно, второй получит 409 и понятное сообщение,
а не тихую перезапись чужой брони.

**Личные данные не утекают.** `GET /api/state` отдаёт только имя дарителя
(и `null`, если он выбрал «пусть будет сюрприз»). Телефон, пожелание и время
видны исключительно в админке.

**Свою бронь можно снять.** При бронировании гость получает одноразовый токен,
он хранится в его браузере. Кнопка «отменить» появляется только у того, кто
бронировал; чужую бронь снять нельзя. Родители могут снять любую — из админки.

**Сессия админа** — HttpOnly-кука, подписанная HMAC, живёт неделю. Пароль
сравнивается за постоянное время, на попытку входа стоит задержка.

**Правка каталога.** В админке можно добавить, изменить и удалить подарок,
выбрать картинку из 21 нарисованной или дать https-ссылку на свою. Всё, что
приходит от клиента, проверяется на сервере повторно: `javascript:` и `data:`
в качестве картинки не пройдут.

**Ссылка на магазин.** Необязательное поле у подарка. Если она задана, гость
увидит кнопку «Где купить подарок» сразу после брони — пока она на экране,
окно не закрывается само, иначе нажать не успеть.

## Заметки

- Иллюстрации подарков — SVG в `assets/js/sprite.js`. Чтобы добавить новую,
  впишите туда `<symbol id="g-имя" viewBox="0 0 100 100">…</symbol>`, и она
  сама появится в выборе картинок в админке.
- Ссылок на админку на сайте нет — заходите по прямому адресу `/admin`.
  `admin.html` закрыт от индексации через `noindex`, но это не защита: защита в пароле.
- Локальный `.data/db.json` в репозиторий не попадает.
